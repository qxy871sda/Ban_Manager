# 全局黑名单管理器 (Ban Manager)

## 简介
本插件能为 麦麦（Bot） 在适配器内`全局屏蔽用户`名单内`添加/移除`QQ用户提供支持（工具调用）。它也支持管理员通过指令手动加入`全局屏蔽用户`，也可以在`config.toml`中自定义调用规则自主判定并屏蔽对应发言者。本插件会将对应用户QQ 自动/双向同步至 `SnowLuma`或`NapCat`配置器内`config.toml`中的`ban_user_id = []`条目，实现更底层、更高效的无感消息过滤。

## 适配的适配器版本
- **SnowLuma/NapCat 统一适配器**（`plugins/maibot-team_snowluma-adapter`）：自 1.0.2 / 1.1.x 起，真正生效的用户黑名单是 `[filters].ban_user_id`，本插件已自动识别并写入该节（旧版的 `[chat].ban_user_id` 已不再参与过滤）。
- **旧版独立适配器**（如 `plugins/maibot-team_napcat-adapter`）：沿用 `[chat].ban_user_id`，同样兼容。
- 如果两份名单节同时存在（统一适配器升级后可能残留旧的 `[chat]`），插件会把两节一起读写，避免留下互相冲突的两份名单。
- 插件目录被改名（例如把下划线改成点号）时，插件会按 `_manifest.json` 里声明的插件 ID 反查适配器配置，无需改配置。
- 插件写入适配器 `config.toml` 后，麦麦会通过文件监听自动热重载适配器配置，**不需要手动重启**（重载瞬间适配器可能短暂重连一次）。

## ⚠️ 安全与权限声明（使用前必读）

本节如实说明本插件的文件访问范围与权限边界。这些行为是本插件能实现「跨插件同步屏蔽名单」的前提，也是使用前必须知情的部分。

### 1. 会写入哪些文件（跨插件写入）

- 本插件自身：`plugins/ban_manager/config.toml` → 只写 `[plugin].ban_user_id`。
- 目标适配器：`plugins/maibot-team_snowluma-adapter/config.toml`（统一适配器）→ 只写 `[filters].ban_user_id`；旧版独立适配器 `plugins/maibot-team_napcat-adapter/config.toml` → 只写 `[chat].ban_user_id`。若两节都存在则一起写，保持两份名单一致。
- 只改上述这一个键：其它键、其它节的内容不会被删除或改写（但整份文件会被 TOML 库重新序列化，**手写注释与排版可能被规范化**）。
- **为什么会越界**：SDK 没有向普通插件开放「修改其它插件配置」的能力（`component.update_plugin_config` 仅授予内置插件管理插件），也没有屏蔽名单相关的官方能力，因此本插件只能直接读写目标配置文件。这意味着**这些写入不在 SDK 的能力保护范围内**：目标适配器若调整了配置结构，本插件可能写错位置或写入失败。请自行评估后再启用。
- 写入后宿主会监听到文件变化并热重载适配器配置，因此**不需要重启麦麦**；重载瞬间适配器可能短暂重连一次。

### 2. 触发写入的时机

- `adapter_type = none`（默认）：完全不读写任何适配器配置，只维护本插件自身名单。
- 插件启动（`on_load`）：把适配器已有名单与本插件名单**取并集**合并，仅在两侧集合不同时才回写，**只增不减，不会清空任何一侧的名单**。
- WebUI 修改本插件名单、执行 `/拉黑`、`/解除`、或麦麦调用 `add_to_global_blacklist` 工具时：同步写入。
- 增删基准是「本插件名单 ∪ 适配器现有名单」，不会覆盖掉你手动写进适配器里的 QQ 号。

### 3. 会读取哪些内容

- 目标适配器的 `config.toml`（读取名单）。
- 当约定目录名不存在时，扫描 `plugins/*/` 并读取其 `_manifest.json`，**仅用于按插件 ID 定位适配器目录**。
- 通过宿主能力 `message.get_by_id` / `message.get_recent` 读取**被举报的那条消息的内容**，以及在必要时读取当前聊天流最近消息（最多 40 条，仅用于昵称唯一匹配兜底）。这是身份判定所必需，**不会读取或保存与本插件无关的聊天记录，也不会把这些内容写出到任何地方**。

### 4. 明确不做的事

- **不联网**：没有任何 HTTP/WebSocket 请求，不上传任何数据（QQ 号、群号、聊天内容、配置、token 均不外发）。
- **不执行命令**：没有 `subprocess` / `shell` / `eval` / `exec`，不会下载并执行远程代码。
- **不引入宿主基线之外的新依赖**：仅使用标准库（`json` / `os` / `re`）+ 宿主自带的 `tomlkit`、`pydantic`、`maibot_sdk`；`_manifest.json` 的 `dependencies` 为空数组。
- **不修改宿主数据库**，也不改动适配器配置里除名单键以外的任何内容。

### 5. 恢复与止损

- 启用前请先备份：`plugins/maibot-team_snowluma-adapter/config.toml`（或整个适配器插件目录）；WebUI 保存插件配置时宿主也会在插件目录生成 `config_back/` 备份。
- 想彻底停止一切跨插件写入：把 `adapter_type` 设为 `none` 后重载/重启插件。
- 名单被改坏时：直接用备份还原适配器 `config.toml`。本插件只接受纯数字 QQ 号，写入前会过滤非数字内容。

### 6. 与官方插件规范的对应说明

- `capabilities` 只声明**实际使用**的能力，且都真实存在于 SDK：`send.text`（群内通知与指令回复）、`config.get`（读取麦麦自身账号，用于「禁止拉黑自己」）、`message.get_by_id`（按 `msg_id` 反查发送者并核对原文）、`message.get_recent`（昵称唯一匹配兜底）。
- 上述跨插件文件写入**无法用官方能力声明表达**，因此在 README 中显式披露；若日后官方提供了「写入其它插件配置」的能力，本插件应改为使用官方能力。
- 本插件不使用 shell、网络与数据库能力，因此也没有声明相关 capabilities。

## 核心功能
- **主动忽略消息**：通过调用 OneBot 适配器的 `ban_user_id` 机制，bot 会在适配器层直接丢弃黑名单内用户的消息，实现主动屏蔽（非群内禁言），此屏蔽为全局的屏蔽。
- **名单同步**：自动检测并同步 SnowLuma/NapCat 适配器的黑名单，支持在 WebUI 直接管理屏蔽名单，修改后自动实时同步。增删以“本插件名单 ∪ 适配器现有名单”为基准，不会覆盖掉你手动写进适配器里的 QQ 号。
- **以工具调用**：内置 `add_to_global_blacklist` 工具，允许 麦麦 在检测触发到用户自定义设置的规则后，自主决定将其拉入黑名单。
- **身份核查（不会认错人）**：工具必须同时传入 `msg_id` 与违规原文 `evidence`。插件用 `msg_id` 反查那条消息的发送者 QQ 号，并核对 `evidence` 是否真的出现在这条消息里；任何一项对不上都会**拒绝执行**并把该消息的实际内容回给麦麦，让它重新核对，而不是凑合着拉黑一个“看起来像”的人。
- **拒绝猜身份**：只有当某个昵称在最近消息里**唯一**对应一个 QQ 号时才允许按昵称兜底反查；昵称撞车（同名不同人）直接拒绝。绝不会把昵称、群名片当成 QQ 号。
- **拒绝拉黑自己**：解析出的发送者是麦麦自己（`bot.qq_account` / `bot.platforms` 声明的账号）时直接拒绝，防止选错消息导致自黑。
- **灵活的群聊过滤**：支持白名单/黑名单模式，您可以精确指定哪些群聊受此插件规则影响。

## WebUI 配置说明
（**建议在启用前先备份原有适配器的 `config.toml` 或其中 `ban_user_id = []` 的内容**）
- **当前适配器类型**：
    - `none`：默认项，仅维护本插件自身名单，不读写任何适配器配置。
    - `snowluma`：SnowLuma/NapCat 统一适配器（`plugins/maibot-team_snowluma-adapter`），插件会识别并同步真正生效的 `[filters].ban_user_id`。
    - `napcat`：旧版独立 `plugins/maibot-team_napcat-adapter`（名单在 `[chat].ban_user_id`）。
    - `all`：同步所有能找到的适配器，请先备份各适配器配置。
- **发送群内通知**：开启后，当有用户被屏蔽时，bot 会在群内发送成功等通知消息。
- **修改屏蔽名单**：支持在此界面直接添加、编辑或删除 QQ 号，修改后自动同步至各适配器。名单以并集方式合并，不会因为某一侧为空而清空另一侧的名单。
- **工具描述/调用规则**：发送给 麦麦 的工具描述，可在此自定义拉黑的判定标准（如：把“谩骂”改成“骚扰”等）。默认文案已经写明「只处理明确指向麦麦的发言、禁止对号入座、判断不了就不要调用、必须传 msg_id 与原文」等约束，改动时建议保留这些约束，否则容易误拉黑无辜群友。

## 指令列表 (管理员可用)
*   `/拉黑 <QQ号> [原因]` / `/屏蔽 <QQ号> [原因]`：手动将指定用户加入全局屏蔽名单（不会拉黑麦麦自己）。
*   `/解除 <QQ号>`：将指定用户从全局屏蔽名单中移出。
*   `/屏蔽名单` / `/拉黑名单`：列出当前所有被屏蔽的 QQ 号。

## ⚠️ 免责与注意事项
1. **屏蔽机制**：本插件是通过适配器配置文件中的 `ban_user_id` 实现的“不接收消息”，并非 QQ 群内的禁言功能，被屏蔽的用户依然可以在群内正常发言，但 bot 将完全看不见其消息。
2. **配置文件备份**：在将 `adapter_type` 修改为 `all` 或批量迁移名单前，请务必备份您的适配器 `config.toml` 文件。
3. **加载顺序**：本插件在启动时会自动把适配器中已有的名单合并进自身配置，确保 WebUI 能够完整显示现有屏蔽记录。
4. **工具调用的自我纠错**：`msg_id` 找不到、原文 `evidence` 对不上、昵称无法唯一定位或目标就是麦麦自己时，工具都会返回失败原因而不会拉黑任何人；麦麦收到失败原因后应当重新核对上下文再决定，而不是换个人拉黑。

## 兼容性与依赖
- **宿主**：MaiBot `1.0.0` ~ `1.99.99`（以 `_manifest.json` 的 `host_application` 为准）；**SDK**：`2.0.0` ~ `2.99.99`。
- **Python**：使用宿主自带环境即可（≥ 3.10）。
- **额外依赖**：无（`dependencies` 为空数组，不新增任何第三方包）。
- **适配器**：需另外安装并启用 SnowLuma/NapCat 统一适配器（推荐）或旧版独立 NapCat 适配器；未安装时插件只能维护自身名单，等价于 `adapter_type = none`。
- **适配器版本**：统一适配器 1.0.2+（名单在 `[filters].ban_user_id`）；更早版本名单在 `[chat].ban_user_id`，两种本插件都能识别与读写。

## 已知限制
1. 适配器配置结构若再次改名或迁移，本插件需要同步更新；目前只自动识别 `[filters].ban_user_id` 与 `[chat].ban_user_id` 两种名单节。
2. 名单只接受纯数字 QQ 号，非数字内容会被过滤掉。
3. 屏蔽是「适配器层不接收消息」，不是群内禁言：被屏蔽的人照常能在群里说话，只是麦麦看不见。
4. 修改名单会触发适配器配置热重载，期间可能短暂重连。
5. 仅适用于 QQ（SnowLuma/NapCat/OneBot v11）平台；其它平台不受影响。
